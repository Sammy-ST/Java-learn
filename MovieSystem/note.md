## 一、权限修饰符疑惑：为什么Service方法全用private？
1. 我的疑问
为什么 addMovie()、deleteMovie()、queryMovie()、banActor() 全部是 private，不用 public？

2. 核心原理（我理解的）
- 面向对象封装思想：只对外暴露唯一入口，隐藏内部细节
- 整个系统只有 start() 是对外开放的（public），是程序唯一大门
- 增删查封杀都是内部工具方法，只在Service类内部调用，不需要外部访问

3. 如果改成public的后果（重大bug）
外部测试类可以绕过菜单，直接强行调用 addMovie()、deleteMovie()，打乱程序逻辑，系统安全性失效。

4. 总结口诀
对外服务用public，内部工具用private。

## 二、Scanner疑惑：为什么没有nextString()？
1. 我的疑问
读取字符串为什么不用sc.nextString()，只能用 sc.next()？

2. 核心知识点
Java Scanner根本没有 nextString() 方法，属于我自己的认知误区。

3. Scanner读取规则（必背）
- sc.next()：读取字符串，遇到空格/回车停止（适合电影名、明星名）
- sc.nextLine()：读取一整行内容（包含空格）
- sc.nextInt()：读取整数
- sc.nextDouble()：读取小数

4. 项目选择原因
本系统的电影名、主演姓名都不带空格，所以用 sc.next()最合适、无bug。

## 三、集合删除疑惑：为什么批量删除必须倒序遍历？
1. 我的疑问
封杀明星功能，为什么不能正序遍历，必须倒序遍历删除？

2. 核心bug原理（重点）
ArrayList 删除元素后，后面所有元素会自动向前平移，索引会刷新。
- 正序遍历删多个元素：会跳过元素、出现漏删bug
- 倒序遍历删多个元素：从最后一个索引往前删，前面的索引完全不受影响，永不乱序

3. 两种删除场景区分（超级重要）
- 删除单个元素（下架电影）：增强for循环 + remove(对象) + break ✅ 没问题
- 删除多个元素（封杀明星）：必须 倒序普通for循环 + 索引删除 ✅

## 四、变量赋值疑惑：为什么非final变量不会动态更新？
1. 我的疑问
我定义了 private int SIZE = movies.size();，没有加final，可以修改，为什么值永远是0，不会跟着集合动态变化？

2. 最终答案（彻底解惑）
- 成员变量的赋值只执行一次：在对象创建的一瞬间快照赋值
- 项目启动时集合是空的，所以SIZE永久赋值为0
- 不加final的含义：只是我可以手动修改这个变量，不代表变量会自动跟随数据源更新！
- 变量是死数据，集合是动态数据，两者不会自动联动

3. 正确写法
绝对不要定义固定size变量，每次使用实时获取：
for (int i = movies.size() - 1; i >= 0; i--)

## 五、匿名对象 深度理解（我的最大疑惑）
1. 我的疑问
为什么入口可以写 new MovieService().start()？不用定义 MovieService ms = new MovieService(); 赋值变量？

2. 两种写法效果
两种写法运行效果完全一模一样！
// 有名对象：创建对象 + 赋值变量，可以反复使用
MovieService ms = new MovieService();
ms.start();

// 匿名对象：创建对象直接调用方法，无变量名，只用一次
new MovieService().start();

3. 匿名对象核心特点
- 没有引用变量名指向
- 只能当场调用一次方法
- 执行完毕后无引用，会被垃圾回收
- 代码简洁，适合只使用一次的对象

4. 什么时候用有名/匿名对象
- 匿名对象：只调用一次方法（本项目启动入口）
- 有名对象：后续需要多次调用对象的多个方法

## 六、我本次写代码出现的所有低级语法错误复盘
1. 自定义集合无 getName() 方法，正确写法：movies.get(i).getActor()
2. 代码写错符号：equals.(actor) 多了小数点，语法报错，正确：equals(actor)
3. 把动态集合长度赋值给固定成员变量，导致数据永久不变

## 七、最终整体项目规范总结
1. Service层：对外单一public入口，内部功能全部private封装
2. 单元素删除：增强for循环删除，删完break
3. 多元素删除：必须倒序索引遍历删除
4. 动态数据禁止用变量缓存，实时调用方法获取
5. 单次调用对象优先用匿名对象，简洁高效
