## 1. 整体学习功能与流程

这次我练习的是Java文本文件IO读写+集合排序的综合案例，核心功能很清晰：**读取本地打乱顺序的《出师表》TXT文件**，把所有文本行存到集合中，通过自定义规则重新排序，最后把排好序的内容，写入一个全新的TXT文件里。

我自己总结的核心流程：**读取文件 → 存入List集合 → 自定义规则排序 → 遍历集合写出文件 → 关闭所有流释放资源**，这也是文本IO综合练习的标准流程。

## 2. IO流全套核心知识点复盘

### 2.1 字节流和字符流的本质区别（我最容易混淆的点）

之前我一直分不清字节流和字符流，现在彻底弄懂了：**两者的核心区别就是适配的文件类型不同，处理中文的效果不同**。

- **字节流（FileInputStream / FileOutputStream）**：属于万能流，只识别二进制0和1，不认识文字。适合处理图片、视频、压缩包等非文本文件，**绝对不适合处理中文**，极易出现乱码，这也是为什么我不能用FileOutputStream直接写本次的文本内容。

- **字符流（FileReader / FileWriter）**：专门为文本、中文设计的流，自带字符翻译功能，能直接识别汉字、英文、换行符，处理文本文件不会乱码，是本次练习的首选流。

### 2.2 转换流的作用与使用场景

我本次进阶练习用到了转换流，之前不理解为什么多此一举，现在明白用途了：**转换流是字节流转字符流的转换器**，底层是字节流，外层包装成字符流，最大的优势是**可以手动设置编码格式**，彻底解决中文乱码问题。

- `InputStreamReader`：将字节输入流 转换为 字符输入流
- `OutputStreamWriter`：将字节输出流 转换为 字符输出流

我总结的底层公式：**基础字节流 + 转换流 = 可自定义编码的高级字符流**，比原生的FileReader、FileWriter更灵活。

### 2.3 Buffer缓冲流的核心作用（重点理解）

之前不懂为什么要额外加Buffered缓冲流，现在彻底通透：普通的基础流（FileReader/FileWriter、字节流）每次读写数据，都会直接和硬盘交互，频繁操作硬盘，速度极慢、效率极低。

**而带Buffer的缓冲流**，会在内存中开辟一块缓冲区，先把数据暂存在内存里，攒够一批数据后再统一和硬盘交互，大幅提升读写效率。

除此之外，缓冲流有两个专属方法，是基础流没有的，也是本次代码的核心：
- `BufferedReader.readLine()`：可以一次性读取一整行文本，不用逐个字符读取
- `BufferedWriter.newLine()`：可以自动换行，不用手动拼接换行符，保证文本格式整齐

**简单记：带Buffer就是提速、好用、支持按行读写。**

## 3. 本次代码致命报错原因总结

我之前代码爆红、出现大量 **Unexpected token** 报错，核心原因只有一个，是我语法结构不熟练导致的：**所有业务执行代码，不能直接写在类里面，必须全部放在main方法中**。

Java的固定语法规则：类体中只能定义成员变量、成员方法，`try-catch`、循环、流对象创建、逻辑代码等可执行代码，一律不能裸奔在类中，必须包裹在方法（`main`主方法）里，这是本次所有语法报错的根源。

## 4. IO流变量定义疑惑点彻底弄懂

我之前一直疑惑：为什么要先写 `BufferedReader br = null;` 再重新赋值 `br = new BufferedReader(isr);` 感觉重复多余，现在彻底理解了两层写法的意义。

### 4.1 两行代码的不同作用

1. **第一行：`BufferedReader br = null;`**
   - 仅声明变量、初始化赋值为空，没有创建真实的流通道，暂时没有读写文件的能力。
   - **核心作用**：扩大变量作用域，让这个变量在`finally`代码块中也能识别，方便最后统一关闭流资源。如果只在`try`内部定义变量，`finally`会找不到变量，无法关流。

2. **第二行：`br = new BufferedReader(isr);`**
   - 真正创建缓冲流对象，绑定文件读写通道，赋予`br`读写文件的能力。
   - 赋值之后，`br`才能调用`readLine()`方法读取文件内容。

### 4.2 优化写法（可合并）

熟练之后可以直接合并成一行，简化代码，效果完全一致：

```java
BufferedReader br = new BufferedReader(new InputStreamReader(new FileInputStream(iPath)));
```

## 5. List集合读写逻辑详细拆解

### 5.1 为什么不用数组，要用List集合？

我之前疑惑读写文件为什么不用普通数组，现在明白：**文件的行数是不固定的**，数组长度固定，无法适配动态的文本行数。而`ArrayList`是动态变长集合，可以自动根据文本行数扩容，适配性更强，专门用来存储不确定数量的数据。

### 5.2 读取逻辑

通过`while`循环配合`readLine()`逐行读取文本，每读取一行内容，就通过 `list.add(line)` 存入集合，循环结束后，整个文件的所有文本行，全部有序存放在List集合中。

### 5.3 写出循环逻辑（我之前最看不懂的部分）

集合无法直接写入文件，必须逐条取出数据，所以需要`for`循环遍历集合，逐行写出，我逐行拆解理解：

```java
for(int i = 0; i < list.size(); i++) {
    String content = list.get(i);
    bw.write(content);
    bw.newLine();
}
```

- `list.size()`：获取集合中存储的文本总行数，作为循环结束条件
- `list.get(i)`：根据下标`i`，取出集合中对应的单行文本
- `content`：临时字符串变量，相当于数据中转站，只在当前循环生效，存储当前取出的单行文本
- `bw.write(content)`：把临时存储的文本内容，写入目标文件
- `bw.newLine()`：每写完一行，自动换行，避免所有文本挤在同一行，保证格式和原文件一致

**核心总结：集合只负责临时存储数据，想要写入文件，必须循环逐条取出！**

## 6. Sort排序&Comparator接口最深疑惑解答

### 6.1 为什么Collections不用new？归属是什么？

这是我本次最大的疑惑之一，现在彻底搞懂：**`Collections`是工具类**，内部所有方法都是`static`静态方法。

**静态方法属于类本身，不属于对象**，所以不需要`new`创建实例，直接通过 `类名.方法名()` 即可调用。同类工具类还有`Math`、`System`，都是全局共享工具，不用实例化。

### 6.2 为什么要new Comparator？不能直接用吗？

我之前疑惑：既然有`Comparator`，为什么还要`new`、重写方法？原因很简单：**`Comparator`是接口**。

接口的特点：没有方法体、没有构造方法、不能直接实例化、没有默认的排序规则。系统不知道我要按什么规则排序（按数字、字母、长度还是首字符），所以**必须我自己定义规则**。

代码中 `new Comparator<String>(){}` 是**匿名内部类写法**，作用是当场实现接口、重写`compare`方法，给`sort`方法指定自定义排序规则。

### 6.3 排序代码逻辑详解

```java
Collections.sort(list, new Comparator<String>(){
    @Override
    public int compare(String a, String b){
        return a.charAt(0) - b.charAt(0);
    }
});
```

- 参数`a`、`b`：代表集合中任意两个待比较的文本行
- `a.charAt(0)`：取出当前行第一个字符（也就是文本开头的数字1、2、3...）
- `a字符减b字符`：实现从小到大升序排序

**简单说**：我通过重写方法，告诉程序「按照每行第一个数字排序」，程序就会按照我的规则整理集合内容。

## 7. 工具类 vs 实例对象终极区分

这是我经常混淆的知识点，专门整理了区分标准和用法，以后不会再错：

### 7.1 实例对象（必须new）

属于独立的个体，每个对象都是独一无二的，方法都是非静态的，必须先`new`创建对象，再通过 `对象名.方法()` 调用。

**本次代码中的实例对象**：`ArrayList`、`BufferedReader`、`BufferedWriter`，对应的`list.add()`、`br.readLine()`都是实例方法。

### 7.2 工具类（不用new）

属于全局共享工具，所有方法都是`static`静态方法，归属于类本身，直接 `类名.方法()` 调用，无需创建对象。

**常见工具类**：`Collections`、`Math`、`System`，对应用法：`Collections.sort()`、`Math.max()`、`System.out.println()`。

## 8. 个人梳理的标准代码执行流程

结合本次练习，我自己梳理出完整、标准的文本IO排序流程，逻辑通顺、无漏洞：

1. 定义输入、输出文件的绝对路径，确定读写文件位置
2. 提前声明缓冲流变量并赋值`null`，统一作用域，方便后续关流
3. 通过`try-catch-finally`搭建异常处理框架，捕获所有IO异常
4. 三层包装流（字节流+转换流+缓冲流），开启文件读取通道
5. `while`循环逐行读取文本，将所有内容存入List集合
6. 调用`Collections`工具类的`sort`方法，通过重写`Comparator`方法自定义排序规则
7. 创建输出流通道，`for`循环遍历排序后的集合，逐行写入新文件并自动换行
8. `finally`代码块中，判断流对象非空，统一关闭所有流，释放硬盘资源

## 9. 本次练习所有踩坑报错汇总

把本次写代码遇到的所有报错和原因整理下来，避免下次重复踩坑：

- **Unexpected token / 分号缺失**：可执行代码没有放在`main`方法内，代码结构错误
- **Unhandled exception 未处理异常**：IO流属于受检异常，必须用`try-catch`捕获，否则爆红
- **变量重复定义**：同一个代码作用域内，重复定义同名变量
- **中文乱码**：误用字节流处理文本文件，没有使用字符流/转换流
- **排序无效**：未正确重写`compare`方法，或取错对比字符位置

## 10. 极简记忆

1. 文本读写用字符流，媒体文件用字节流
2. Buffer缓冲提效率，专属方法可按行读
3. 接口无规则需重写，匿名内部类补逻辑
4. 静态工具不用new，实例对象必创建
5. 集合存数需遍历，逐条写入文件中
6. 所有执行业务码，全部放入main方法
