## 三、核心知识点梳理
### 1. 接口 Switch
- 作用：统一所有家电**开关按压**行为
- 抽象方法：`void press()` 实现设备状态反转

### 2. 家电父类 JD
1. 成员变量：`private`修饰`name`设备名、`status`开关状态
2. 使用`@Data`注解自动生成`get/set`方法，省去手写
3. 重写接口`press()`方法：`status = !status`实现开关切换
4. 子类继承父类，通过**set方法**给父类私有属性赋值

### 3. 子类书写规范（TV/空调/灯具等）
1. 继承父类`JD`
2. 编写有参构造方法
3. 构造内调用父类`setName()`、`setStatus()`完成赋值
4. 无需重写开关方法，直接复用父类逻辑

### 4. 单例模式：智能中控 SmartHomeControl
#### 核心三段代码详解
```java
// 1. 私有空构造方法
private SmartHomeControl(){}
// 2. 内部创建唯一静态常量对象
private static final SmartHomeControl INSTANCE = new SmartHomeControl();
// 3. 公共静态获取实例方法
public static SmartHomeControl getInstance(){
    return INSTANCE;
}
```
1. **私有构造方法作用**
    - 禁止外部使用`new`创建中控对象
    - 仅用于**限制对象创建权限**，不需要传参赋值
    - 区分：家电构造器用来赋值，中控私有构造只用来“锁死创建”
2. **静态常量 INSTANCE**
    - `static`：全局共享唯一
    - `final`：常量不可修改、不可重新赋值
3. **getInstance() 方法**
    - 静态方法：**类名直接调用**，无需创建对象
    - 作用：向外提供唯一中控实例，统一领取使用
    - 只有`get`没有`set`：中控对象固定不变，只可取不可替换

#### 中控内置方法
- `control()`：接收家电对象，调用开关方法切换状态
- `printAll()`：遍历家电数组，打印所有设备名称与开关状态

## 四、编写过程出现的错误&解决办法
1. **报错：找不到setName/setStatus方法**
    - 原因：父类未写`get/set`，忘记添加`@Data`注解
    - 解决：给父类添加`lombok`的`@Data`注解，自动生成存取方法
2. **报错：私有属性无法直接访问`super.name`**
    - 原因：父类成员变量用`private`私有化，子类不能直接访问
    - 解决：子类构造方法调用父类`set`方法赋值，不直接访问私有变量
3. **for循环遍历数组写法错误**
    - 错误写法：`for(JD i:devices.length)`
    - 错误原因：增强for循环只能遍历数组/集合，不能遍历数字长度
    - 正确写法：普通`for(int i=0;i<devices.length;i++)`遍历下标
4. **子类构造调用父类有参构造报错**
    - 原因：父类无对应有参构造
    - 解决：放弃`super(参数)`调用，改用`set`方法赋值

## 五、易混淆知识点区分
### 1. 有参构造 VS 无参构造
1. **无参构造**：创建对象不赋值，后续用`set`赋值
2. **有参构造**：创建对象直接传入参数，一步完成赋值
3. **私有无参构造**：**不用于赋值**，仅用于禁止外部new对象（单例专用）

### 2. get方法 VS set方法
1. `get`：获取属性数据，只读不修改
2. `set`：修改/设置属性数据，可写入修改
3. 单例`getInstance`：获取唯一对象，无`setInstance`，禁止替换实例

### 3. 家电类 VS 中控类
1. **家电类**：有名称、有状态，需要构造方法赋值，负责自身开关状态
2. **中控类**：无自有属性，仅作为工具调度设备，全局唯一，禁止多次创建

## 六、学习总结
1. 面向对象继承可以极大复用家电通用代码，减少冗余
2. 接口统一规范行为，让所有家电拥有一致的开关操作
3. 单例模式适合**全局唯一工具类/控制类**，避免多对象造成逻辑混乱
4. 控制台`while+switch`是基础菜单交互常用写法
5. 封装思想：私有属性私有化，仅通过公共方法访问，提高代码安全性
6. 写代码优先排查注解、遍历语法、权限访问三类基础错误
