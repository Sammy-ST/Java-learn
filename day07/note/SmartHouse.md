1. 项目整体概述
1.1 项目简介
基于 Java 面向对象思想开发的控制台智能家居控制系统，结合接口、继承、单例模式、循环分支、数组及 Lombok 注解实现，是典型的 Java 基础综合实训项目。
1.2 核心功能
- 统一家电开关行为规范（接口约束）
- 实现电视、洗衣机、吊灯、空调四类家电管理
- 全局唯一中控设备，统一管控所有家电
- while+switch 实现交互式菜单，可循环控制设备开关
- 实时展示所有家电当前运行状态
1.3 技术栈
Java OOP（继承、接口、封装）、单例设计模式、数组、Scanner 键盘录入、while/switch 流程控制、Lombok

3. 各模块代码功能详解
3.1 接口层（Switch）
作用：抽取公共开关行为，强制所有家电必须实现开关功能，统一代码规范。
3.2 父类（JD）
- 私有属性：name（设备名）、status（开关状态）
- 使用 @Data 注解 自动生成 get/set、toString 等方法
- 重写 press() 方法，实现开关状态反转逻辑
3.3 家电子类
子类无冗余代码，仅提供有参构造，通过父类 set 方法赋值，不使用 super 父类构造调用，规避构造器不匹配报错。
3.4 中控类（SmartHomeControl）
- 私有化构造：禁止外部 new 对象
- 静态常量创建唯一实例
- 提供 getInstance() 唯一获取入口
- 封装控制设备、打印全部状态两大核心方法
3.5 主程序（Test）
- 数组批量存储所有家电对象
- 死循环常驻菜单，switch 分支匹配操作
- 支持设备控制、错误拦截、系统退出

4. 开发全程错误汇总 + 原因 + 解决方案
错误 1：子类直接访问父类私有属性报错
- 报错信息：name has private access in JD
- 错误原因：父类成员变量被 private 私有化，子类无法直接访问 super.name
- 解决方案：放弃直接访问成员变量，通过父类 setName()、setStatus() 赋值
错误 2：找不到 setName / setStatus 方法
- 错误原因：JD 类忘记添加 Lombok @Data 注解，无法自动生成存取方法
- 解决方案：补充 @Data 注解，导入 Lombok 依赖
错误 3：for 循环语法错误（核心低级错误）
- 错误代码：for(JD i:devices.length)
- 错误原因：增强 for 循环只能遍历数组/集合，不能遍历 int 类型的数组长度；变量类型混乱
- 解决方案：改用普通 for 循环，通过下标遍历，正常打印设备序号与状态
错误 4：super(有参构造) 报错
- 错误原因：子类调用父类有参构造，但父类未定义对应双参构造方法
- 解决方案：统一使用 set 方法赋值，不依赖父类有参构造

5. 核心难点：单例模式（彻底吃透）
5.1 核心作用
保证SmartHomeControl 全局只有唯一一个对象，避免多个中控实例导致控制逻辑混乱，贴合真实智能家居「一个总中控」的业务逻辑。
5.2 单例三段核心代码（必考）
// 1. 私有空构造：锁死外部 new 对象权限
private SmartHomeControl(){}

// 2. 静态常量：程序启动直接创建唯一实例（static全局唯一 + final不可修改）
private static final SmartHomeControl INSTANCE = new SmartHomeControl();

// 3. 公开静态方法：唯一对外获取入口
public static SmartHomeControl getInstance(){
    return INSTANCE;
}
5.3 正确调用方式
禁止 new 对象，只能通过类名调用静态方法获取实例：
SmartHomeControl control = SmartHomeControl.getInstance();

6. 构造器知识点：有参 / 无参 / private私有构造
6.1 无参构造
创建对象不赋值，后期通过 set 方法手动赋值，默认自动生成。
6.2 有参构造
创建对象直接初始化属性，一步完成赋值，适合固定参数初始化。
6.3 Private 私有构造（重点误区纠正）
- 不是用来赋值的！
- 唯一作用：禁止外部 new 对象
- 用于单例类、工具类，和家电赋值构造完全无关
6.4 项目使用区分
- 家电类：用构造/set 给设备属性赋值
- 中控类：用私有构造限制对象创建，无需任何赋值

7. 核心疑问答疑汇总（本人提问重点）
7.1 疑问1：私有空构造没有传值，为什么一定要写？
私有构造的作用不是初始化、不是传值，是权限限制，禁止外部通过 new 创建中控对象，保证单例。
7.2 疑问2：中控不需要传值、改状态吗？
改状态、传 name/status 都是家电对象的操作；中控是工具控制器，自身没有属性，只负责调用方法控制设备。
7.3 疑问3：为什么只有 getInstance，没有 setInstance？
- INSTANCE 被final 修饰，是常量，禁止二次赋值
- 单例核心：全局唯一、不可替换
- get 是获取使用，set 是修改替换，中控不允许被替换，因此无 set 方法

8. while+switch 交互逻辑解析
- while(true) 死循环：实现程序常驻，无需重复运行项目，可连续操作
- 实时刷新状态：每次循环先打印所有设备状态，可视化操作结果
- switch 分支：匹配用户输入，精准控制对应设备
- 容错处理：default 拦截非法输入
- 退出机制：输入 0 终止程序，正常退出
