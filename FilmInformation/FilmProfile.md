# 一、项目结构（标准三层架构）
```
FilmProfile/
├── Movie.java          // 电影实体类：封装数据
├── MovieOperator.java   // 电影操作类：处理业务逻辑
└── Test.java            // 测试启动类：程序入口 + 菜单循环
```

1. **Movie.java**：实体类，私有成员变量 + 构造方法 + getter/setter
2. **MovieOperator.java**：业务类，负责展示全部电影、根据ID查询电影、展示菜单
3. **Test.java**：启动类，创建电影数组、创建操作对象、循环菜单

# 二、核心疑问 & 关键问题总结

## 1. 为什么必须用 `m.getId()`，不能用 `m.id`？
- 原因：实体类变量使用 `private` 私有化，外部无法直接访问
- 错误写法：`m.id`（编译报错，私有变量不可直接访问）
- 正确写法：`m.getId()`（通过公共 getter 方法获取）
- 核心思想：**封装** —— 保护数据，统一访问入口

## 2. 静态方法报错：Non-static field 'movies' cannot be referenced
- 报错原因：给 `searchMovieById()` 加了 `static`
- 原理：
  - 静态方法属于类，不能直接访问属于对象的成员变量
  - `movies` 是对象级别变量，必须用实例方法访问
- 解决方案：**去掉 static 关键字**

## 3. 为什么要创建 MovieOperator 操作对象，不直接操作数组？
- 可以直接操作数组吗？**语法可以，但不规范**
- 必须使用操作类的原因：
  1. **职责分离**：数据、业务、启动互不干扰
  2. **代码复用**：方法写一次，任意地方调用
  3. **数据安全**：数组私有化，防止外部随意修改
  4. **企业规范**：面向对象标准开发模式
- 总结：**不直接操作数组 = 专业、安全、易维护**

# 四、易错点总结
1. 私有变量必须用 `getter` 获取，不能直接 `.变量名`
2. 业务方法不要随便加 `static`，避免静态访问错误
3. 查询电影时必须判断是否找到，提升程序健壮性
4. 面向对象开发：**不要把所有代码写在 main 方法里**
5. 实例方法必须通过**对象调用**，不能用类名直接调用
